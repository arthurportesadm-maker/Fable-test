How it works

Three steps to govern every agent action

1

Declare policy in YAML

Allow or deny tools, set spend caps and rate caps, and require human approval for sensitive actions — all first-match-wins and version-controlled.

policies.yaml 
rules:
  - tool: payments.refund
    when: arguments.amount > 250
    effect: require_approval
  - tool: payments.*
    effect: allow
    max_amount: 5000
2

Approve from the CLI

Gated actions pause and wait for a human. An operator reviews the request — with sensitive fields redacted — and approves or denies by ID.

operator shell 
$ tracerail approvals
PENDING  A-1042  payments.refund
$ tracerail approve A-1042
approved · agent unblocked
3

Verify the chain

Every call — allowed, denied, or escalated — is appended to a hash-chained log. Re-verify the whole chain end to end at any time.

operator shell 
$ tracerail verify
OK: audit chain intact
# SHA-256 · every link checked

What is an AI agent control plane?

An AI agent control plane is a layer that sits between an AI agent and the tools it can use, governing every action the agent takes — deciding what is allowed, pausing sensitive actions for human approval, and recording an auditable trail of what happened. Unlike observability tools that only watch and report after the fact, a control plane enforces policy in real time and produces evidence you can verify.

Tracerail is an open-source (Apache-2.0) example of an agent control plane. It runs as a drop-in MCP proxy that adds declarative YAML policies, human approval gates, and a tamper-evident, hash-chained audit trail in front of any MCP-compatible tool server.

FAQ

Frequently asked questions

What does Tracerail do?

Tracerail is a control plane for AI agent actions. It sits between your agent and its tools as a drop-in MCP proxy, recording every action in a tamper-evident audit trail, enforcing declarative YAML policies, and pausing sensitive actions for human approval.

How is it different from LangSmith or Langfuse?

LangSmith and Langfuse are observability and tracing tools: they help you see and debug what your agents did. Tracerail is a control plane: it can stop, gate, and prove actions in real time with policy enforcement, human approval gates, and a tamper-evident audit chain. The two are complementary — observe with one, enforce and prove with the other.

Does it require changing my agent's code?

No. Tracerail is a drop-in proxy for any MCP server. You start your existing MCP server through the Tracerail proxy and point your agent at the proxy. No SDK, no code changes, and no rewrites to your agent.

How does the tamper-evident audit trail work?

Every recorded action is hashed together with the hash of the previous entry, forming a hash chain. Changing or deleting any past entry breaks every hash that follows it, so tampering is detectable. You can run a verify command at any time to confirm the chain is intact end to end.

Does Tracerail help with EU AI Act or SOC 2 compliance?

It is built to support them. Tracerail's automatic, tamper-evident logging maps to EU AI Act Article 12 record-keeping requirements and to SOC 2 CC7 monitoring controls. It produces verifiable exports you can hand to auditors. Tracerail is tooling, not legal advice, but it gives you the evidence those frameworks expect.

Is it open source and self-hosted?

Yes. Tracerail is released under the Apache-2.0 license and runs entirely in your own environment. Your agent traffic, policies, and audit data never have to leave your infrastructure.

What is MCP?

MCP, the Model Context Protocol, is an open standard for connecting AI agents to tools and data sources. Because Tracerail speaks MCP, it works as a transparent proxy in front of any MCP-compatible server, which is how it adds policy, approvals, and audit without code changes.
